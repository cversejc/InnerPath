## 已验证的功能

- 用户申请创建协作契约；命理和心理分别接单，第一专业接单后另一专业仍可接受。
- 通过真实HTTP路由验证心理无法启动S1、命理可启动S1，双方均可读取已分配工作区。
- 验证S1完成后S2交接及所有节点的专业归属；不能越专业修改。
- 使用已批准QA夹具及真实持久化报告资产验证交付、ReportVersion装配、用户报告记录、不可变版本读取、30天日历发布及日志关联。完整报告质量门禁由原报告测试覆盖，这项夹具验证不表示真人个案已通过审核。
- 验证队列合并、冻结技能/范例、失败不发布、原快照重试、重复投递、超时恢复、格式修复、校准重写和审核引用佐证。
- 完成日志可提炼为候选范例；未脱敏不能发布。审核发布后新申请引用该范例，旧申请保持原快照。
- 浏览器验证四个日历技能、维护/示例/记录/评估入口与咨询师专业类型控件。
- 浏览器验证17节报告的章节目录、收起全部、定位并展开成长实验；截图见report-reader.png。

## 页面与真实后台队列

本地合成用户从报告#19的详情页进入日历，提交申请#2，Outbox、Beat和Celery真实消费成功。第一次生成被独立校准拦截：月基调把10月11日列为yellow，但固定色块为red。该错误暴露了重写只处理日项的编排缺口，17次调用后仍未发布。修正为按field_path分别重写月基调/日项，并重新整月校准；新增两项回归覆盖拒绝审核和approved=true附日项补丁两种情况。随后在页面使用原快照重试，保留第一次失败及其原始运行日志。

申请#2第二次执行在校准阶段两次遇到空正文，旧网关仅记录ValueError，无法追溯当时的结束原因。这一历史记录不重写、不推断为已确认的预算耗尽。补全网关的finish_reason、用量及空正文错误分类，并根据官方API说明将新校准版本预算提高到32768；旧申请仍固定16000，未覆盖其快照。
