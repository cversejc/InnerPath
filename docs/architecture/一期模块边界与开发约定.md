# 一期模块边界与开发约定

## 架构方向

项目采用模块化单体。前后端按业务领域组织代码，部署和数据存储保持现状；只有出现明确的独立扩缩容、发布或团队边界时，再评估服务拆分。

一期核心流程是账号与权限、个人报告、决策日历、服务申请与交付、AI 任务和运营管理。服务介绍、用户直接预约和课程展示与学习不进入一期；相关功能实现已移除。

咨询师读取用户报告、报告任务和日历的授权只依据服务申请分配：分配给当前咨询师且状态不是 `withdrawn` 或 `rejected` 的申请才授予访问权。旧预约及课程 API、后台能力、运行时模型已移除；Alembic 前向迁移 `008` 删除相关表。服务申请是当前交付工作流，与已移除的旧预约模块分离。

## 业务领域

| 领域 | 所有者 | 边界 |
|---|---|---|
| Identity | 认证、用户、角色、邀请、会话 | 身份和角色解析，不承载报告或日历规则 |
| Reports | 报告读取、历史报告、报告任务 | 报告内容与任务生命周期 |
| Decision Calendar | 用户日历、日历申请、行动与决策记录 | 日历内容、发布状态和用户记录 |
| Service Requests | 用户申请、咨询师分配、AI 初稿、审校和交付 | 当前报告与日历的工作流和授权关系 |
| Admin | 用户运营、运营视图、审计与导出 | 组合领域能力，不重复实现领域规则 |
| Platform | 数据库、缓存、AI、任务队列、日志 | 跨领域技术能力，不依赖具体页面或路由 |

## 依赖方向

前端页面依赖本领域 API 模块；本领域 API 模块依赖共享 `apiClient`。页面不直接拼接业务 URL，也不从通用业务服务文件导入跨域函数。

后端依赖方向为 API 路由 -> 领域服务 -> 数据模型/外部适配器。路由负责参数、身份和 HTTP 状态码；服务负责业务规则、事务和领域授权；模型负责持久化结构。管理后台可以编排多个领域服务，不能成为领域规则的第二份实现。

跨领域访问通过明确的函数或查询接口完成。避免页面之间互相导入、领域服务之间循环导入，以及把数据库查询散落到无关领域。

## 文件职责约定

- 一个页面或组件聚焦一段用户流程；复杂状态放进同领域 composable，重复展示放进子组件。
- API 模块只封装 HTTP 请求和响应，不承载视图状态或业务决策。
- Python 路由模块按资源域拆分；每个服务模块围绕一类业务能力组织。
- 单文件接近 400 行，或开始同时承担两个以上领域职责时，应评估是否按自然边界拆分；紧密耦合的单一算法或组件不为行数而拆。
- 拆分时保持既有 URL、响应结构和业务行为；需要变更契约时单独说明并迁移。
- Alembic 已发布迁移保持不可变。表结构清理只通过新的前向迁移完成。

## 已完成的整理

1. 前端 API 已归入日历、报告、管理和服务申请领域；服务申请 API 不再放在通用 `utils`。
2. 服务申请的输入规范化、AI 草稿生成、审校、交付和持久化职责已拆分到领域服务模块。
3. 管理 API 已按仪表盘、用户、日历、报告、审计等资源拆路由。
4. 管理台、决策日历和咨询师工作台已拆分页面脚本、子视图、方法与样式；后台样式统一限制在 `.admin-shell` 内。
5. 服务介绍、预约和课程页面与路由已移除；服务申请工作流继续保留。
6. 用户中心已拆分报告、日历、申请和账户设置面板；档案映射、校验和提交载荷集中在个人空间领域模块，页面样式按壳层和面板拆分。
7. 咨询师读取报告、报告任务和日历的授权只依据服务申请分配。
8. 报告详情页已将报告字段兼容、历史内容解析与 Markdown 转换移入报告领域模块；页面样式按基础、命理基础、报告内容、布局和响应式覆盖拆分。
9. 评估表单已复用个人空间的档案映射和 API payload 规范；本次申请的选项、默认情境和严格校验归入评估领域，样式已独立。
10. 个人档案字段组件已将选项、交互脚本和 scoped 样式移出 Vue 文件；组件继续维护一致的字段交互与 `v-model` 契约。
11. 首页视图已将基础样式与响应式规则拆分，并移除未被页面使用的样式选择器。
12. 全局样式已按基础、布局、共享控件和响应式覆盖拆分；导航与介绍页的 scoped 样式独立存放。
13. 评估页编排逻辑已移入评估领域；评估表单选项、校验、提示和生成流程均由该领域管理。
14. 日历申请生命周期已从日历内容与行动记录服务中拆出，用户和管理 API 使用独立申请服务。
15. AI 报告入口只选择生成策略；单步/多步生成、提示构建、结构解析和报告字段映射分别归入报告服务模块。
16. 服务申请 API 按用户、咨询师、任务和管理员路由拆分；原聚合模块保留 router 导出，现有 URL 和注册方式不变。
17. 命理基础适配层已从底层计算器拆出，负责用户资料归一化和报告基础结构组装。
18. 预约、课程及服务介绍的前后端模块、后台管理和运行时模型已移除；迁移 `008` 删除对应数据库表。

## 后续整理顺序

1. 当前活跃模块的结构整理已完成一轮；后续只在新增职责或出现自然边界时继续拆分，避免为了行数制造碎片。
2. 已确认产品未发布，无需处理旧数据或历史授权；预约、课程及相关服务介绍功能已完整移除。
3. 如未来重新引入这些能力，应按新的业务需求设计模块和数据模型，不恢复旧兼容实现。
