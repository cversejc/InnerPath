# 一期模块边界与开发约定

## 架构方向

项目采用模块化单体。前后端按业务领域组织代码，部署和数据存储保持现状；只有出现明确的独立扩缩容、发布或团队边界时，再评估服务拆分。

当前前端已采用领域优先目录；后端保留技术入口与基础设施分层，并开始将跨越多层的业务核心按领域聚合。Reports、Auth 和 Calendar 已按领域聚合核心模型、契约与用例服务；其他后端模块在自然扩展或职责变复杂时再逐步迁移，不做全仓批量搬迁。

一期核心流程是账号与权限、个人报告、决策日历、服务申请与交付、AI 任务和运营管理。服务介绍、用户直接预约和课程展示与学习不进入一期；相关功能实现已移除。

咨询师读取用户报告、报告任务和日历的授权只依据服务申请分配：分配给当前咨询师且状态不是 `withdrawn` 或 `rejected` 的申请才授予访问权。旧预约及课程 API、后台能力、运行时模型已移除；Alembic 前向迁移 `008` 删除相关表。服务申请是当前交付工作流，与已移除的旧预约模块分离。

## 业务领域

| 领域 | 所有者 | 边界 |
|---|---|---|
| Identity | 认证、用户、角色、邀请、会话 | 身份和角色解析，不承载报告或日历规则 |
| Reports | 报告读取、历史报告、报告任务 | 报告内容与任务生命周期 |
| Decision Calendar | 用户日历、日历申请、行动与决策记录 | 日历内容、发布状态和用户记录 |
| Service Requests | 用户申请、咨询师分配、AI 初稿、审校和交付 | 当前报告与日历的工作流和授权关系 |
| Admin | 用户运营、运营视图、审计与导出 | 组合领域能力，不重复实现领域规则 |
| Platform | 数据库、缓存、AI、任务队列、日志 | 跨领域技术能力，不依赖具体页面或路由 |

## 依赖方向

前端页面依赖本领域 API 模块；本领域 API 模块依赖共享 `apiClient`。页面不直接拼接业务 URL，也不从通用业务服务文件导入跨域函数。

后端目标依赖方向为 API 路由 -> 领域服务 -> 数据模型/外部适配器。路由负责参数、身份和 HTTP 状态码；服务负责业务规则、事务和领域授权；模型负责持久化结构。管理后台可以编排多个领域服务，不能成为领域规则的第二份实现。

跨领域访问通过明确的函数或查询接口完成。避免页面之间互相导入、领域服务之间循环导入，以及把数据库查询散落到无关领域。

## 目录归属

前端约定：

| 路径 | 放置内容 |
|---|---|
| `src/views/` | 路由页面的视图组合；页面逻辑和样式较复杂时委托给对应领域目录 |
| `src/features/<domain>/` | 领域 API、页面编排、状态/方法、展示模型、领域组件和领域样式 |
| `src/components/` | 跨领域复用组件；只在单一领域使用的组件留在该领域的 `components/` |
| `src/utils/` | 确实跨领域的纯工具或基础设施；不放置业务 API 聚合服务 |
| `src/styles/` | 全站基础、布局和通用控件样式；页面局部样式归页面或领域所有 |

后端当前采用技术分层目录，新增代码按以下方式归属，并保持同一业务的文件使用一致前缀：

| 路径 | 放置内容 |
|---|---|
| `backend/app/api/v1/` | HTTP 路由和资源路由聚合；复杂资源按职责拆路由文件 |
| `backend/app/domains/<domain>/` | 跨层的领域核心：该领域的持久化模型、契约和用例服务；仅当一个领域已有多组相关模块时采用 |
| `backend/app/schemas/` | 请求、响应和数据交换结构 |
| `backend/app/services/` | 领域规则和用例；拆出的同域模块使用稳定领域前缀 |
| `backend/app/models/` | SQLAlchemy 持久化模型 |
| `backend/app/core/`、`db/` | 跨领域技术能力、数据库连接与会话 |
| `backend/app/tasks/` | 异步任务入口和任务编排 |

当某个后端领域已有多组路由、服务和契约，且跨域改动频繁时，可将模型、契约和用例服务成组迁入 `app/domains/<domain>/`。HTTP 路由继续由 `api/v1` 暴露，Celery 等基础设施入口继续由 `tasks/` 装配；领域代码不得反向依赖这些入口。避免只为目录形式统一而批量移动稳定代码。迁移时明确导入边界，并同步调整该领域测试。

## 技术栈与共享实现

依赖版本以仓库清单为准：前端使用 Vue 3、Vue Router、Vite、Axios 和 Vant 4；后端使用 FastAPI、Pydantic、SQLAlchemy、PostgreSQL、Redis 与 Celery。移动端表单和交互控件优先使用 Vant；不再引入承担同类职责的第二套 UI 库。

复用约定：

- HTTP 请求统一通过 `src/utils/apiClient.js`；领域 endpoint 放在对应的 `src/features/<domain>/api.js`。
- 全站导航、页脚和图标分别复用 `BrandNav`、`BrandFooter`、`IconMark`；移动导航由 `BrandNavMobileMenu` 承担。
- 测评和用户中心的档案字段/摘要优先复用 `ProfileFields`、`ProfileSummary`；领域专用展示组件不提升为全局组件。
- 通用色彩、字体、间距、按钮和表单规范以 `design-system/innerseek/MASTER.md` 与 `src/styles/` 为准；新增全局样式应落在对应基础、布局或控件文件中。
- 移动端通用交互优先复用 Vant 4 控件；按组件引入并配套引入该组件样式，禁止无差别全局注册整套组件。Vant 主题变量统一映射在 `src/styles/vant.css`，使用项目设计 token；品牌导航、档案摘要等组合组件仍由项目组件负责。表单字段应保留实际输入控件上的标签和错误关联语义；控件库无法承载时沿用项目原生控件与共享样式。
- 提取共享组件或工具前先搜索现有实现；只把跨页面/领域的稳定能力放入共享目录，避免产生只转发一次的包装层。

## 文件职责约定

- 一个页面或组件聚焦一段用户流程；复杂状态放进同领域 composable，重复展示放进子组件。
- API 模块只封装 HTTP 请求和响应，不承载视图状态或业务决策。
- Python 路由模块按资源域拆分；每个服务模块围绕一类业务能力组织。
- 单文件接近 400 行，或开始同时承担两个以上领域职责时，应评估是否按自然边界拆分；紧密耦合的单一算法或组件不为行数而拆。
- 拆分时保持既有 URL、响应结构和业务行为；需要变更契约时单独说明并迁移。
- Alembic 已发布迁移保持不可变。表结构清理只通过新的前向迁移完成。
- 前端纯逻辑测试使用 Node 内置 `node:test`，后端测试使用 `pytest`；测试文件靠近对应领域或使用 `backend/tests/` 的既有组织方式。

## 已完成的整理

1. 前端 API 已归入日历、报告、管理和服务申请领域；服务申请 API 不再放在通用 `utils`。
2. 服务申请的输入规范化、AI 草稿生成、审校、交付和持久化职责已拆分到领域服务模块。
3. 管理 API 已按仪表盘、用户、日历、报告、审计等资源拆路由。
4. 管理台、决策日历和咨询师工作台已拆分页面脚本、子视图、方法与样式；后台样式统一限制在 `.admin-shell` 内。
5. 服务介绍、预约和课程页面与路由已移除；服务申请工作流继续保留。
6. 用户中心已拆分报告、日历、申请和账户设置面板；档案映射、校验和提交载荷集中在个人空间领域模块，页面样式按壳层和面板拆分。
7. 咨询师读取报告、报告任务和日历的授权只依据服务申请分配。
8. 报告详情页已将报告字段兼容、历史内容解析与 Markdown 转换移入报告领域模块；页面样式按基础、命理基础、报告内容、布局和响应式覆盖拆分。
9. 评估表单已复用个人空间的档案映射和 API payload 规范；本次申请的选项、默认情境和严格校验归入评估领域，样式已独立。
10. 个人档案字段组件已将选项、交互脚本和 scoped 样式移出 Vue 文件；组件继续维护一致的字段交互与 `v-model` 契约。
11. 首页视图已将基础样式与响应式规则拆分，并移除未被页面使用的样式选择器。
12. 全局样式已按基础、布局、共享控件和响应式覆盖拆分；导航与介绍页的 scoped 样式独立存放。
13. 评估页编排逻辑已移入评估领域；评估表单选项、校验、提示和生成流程均由该领域管理。
14. 日历申请生命周期已从日历内容与行动记录服务中拆出，用户和管理 API 使用独立申请服务。
15. AI 报告入口只选择生成策略；单步/多步生成、提示构建、结构解析和报告字段映射分别归入报告服务模块。
16. 服务申请 API 按用户、咨询师、任务和管理员路由拆分；原聚合模块保留 router 导出，现有 URL 和注册方式不变。
17. 命理基础适配层已从底层计算器拆出，负责用户资料归一化和报告基础结构组装。
18. 预约、课程及服务介绍的前后端模块、后台管理和运行时模型已移除；迁移 `008` 删除对应数据库表。
19. Reports 后端试点已将模型、API 契约和报告/任务用例服务聚合到 `app/domains/reports/`；HTTP 路由与 Celery worker 入口仍保留在技术适配层。
20. Vant 4.10.2 已作为移动端通用控件库接入；主题变量映射到项目设计 token，共享档案操作按钮与移动端 ActionSheet/Tabbar 已迁移。
21. 日历行动记录表单已复用 Vant Field 与 Button；平台原生下拉选择继续保留，业务状态仍由日历领域事件维护。
22. 共享档案的性别、历法、出生时间选项卡和个人中心画像折叠入口已使用 Vant Button；选项状态与 `ProfileFields` 事件契约保持不变。
23. 认证契约和认证、会话、邀请用例已归入 `backend/app/domains/auth/`；API 路由仍是 HTTP 适配层，员工邀请契约不再放在日历 schema。
24. 日历模型、契约、日历请求、内容查询与发布、行动记录和 AI 生成已归入 `backend/app/domains/calendar/`；员工可见性由跨领域应用服务执行，服务申请交付只依赖日历领域接口。
25. 首页与关于页的行动入口使用 Vant Button；路由行为和项目 CTA 样式仍由现有视图与设计 token 管理。
26. 服务申请表单的性别、历法、出生时间选项和提交操作使用 Vant Button；原生输入、字段错误语义和申请状态由服务申请领域继续管理。
27. 评估流程的步骤操作和关注主题选项使用 Vant Button；主题卡片样式由评估领域覆盖 Vant 内部 slot 布局，文本输入和复选框保留原生语义。

## 后续整理顺序

1. 当前活跃模块的结构整理已完成一轮；后续只在新增职责或出现自然边界时继续拆分，避免为了行数制造碎片。
2. 已确认产品未发布，无需处理旧数据或历史授权；预约、课程及相关服务介绍功能已完整移除。
3. 如未来重新引入这些能力，应按新的业务需求设计模块和数据模型，不恢复旧兼容实现。
