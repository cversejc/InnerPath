# 咨询师报告分析链路实施记录

来源：[产品分析框架](产品分析框架.md)，2026-10-04。该文档作为产品需求和分析知识使用，其中的 AI 指令只进入对应系统技能，不作为执行环境指令。

保留 S1–S6 六步，程序生成事实，AI 提出候选，咨询师确认后才能向下游传播。每个覆盖项固定一个内部分析片段标识；缺失信息须明确暂缓及原因，不得跳项或编造。实际客户缺失数据不自动补全；青鸟验收使用标注的演示假设。

## S1 命理看盘

- 程序：使用已有 lunar-python 1.4.8，修正按立春/节气取四柱和农历时分丢失；计算藏干十神、阴阳五行、干支合冲刑害、大运起止。紫微保留全部主辅星、亮度、生年四化与 48 条宫干飞化、命身福德与三方四正。
- AI：完整覆盖八字十项、紫微四项。格局/旺衰/用神属解释判断，不能拿十神计数当旺衰，也不能拿命盘当心理事实。
- 人工：确认出生信息/历法/时区/流派、格局/喜忌和扩展宫位，逐项审核。未知时辰不算时柱、紫微和精确起运。
- 工作台：显示真实计算摘要、角色分工、14 项可展开清单及待确认数量；未确认全部分析条目无法完成节点。
- 验证：11 项基础测试后扩展至 33 项技能/流程/边界测试均通过。前端旧断言仍引用已替换章节名，按当前有效标题修正；前端测试和构建另行通过后提交。

排盘 API 核对：通过 Context7 `/6tail/lunar-python`，参考 [EightChar 官方源文档](https://github.com/6tail/lunar-python/blob/master/_autodocs/api-reference/EightChar.md)。明确晚子时 sect=2，起运 sect=2，中国 UTC+8 民用钟表时间，暂不校正真太阳时。

UI 沿用现有设计系统。ui-ux-pro-max 搜索未命中相关的渐进展示指引，展开清单的安排属于基于当前工作台的设计判断。

## S2 命理与心理对应

8 项覆盖双层映射、十神、十四星曜、面具、阴影、情结、激活路径和内在权威。知识参考存入技能版本，运行时注入且记录快照；人工后续修改的技能知识随版本使用。心理判断必须回到用户现实自述，保护功能和反证都需说明，不补造童年/疾病。合成教学样例进入既有技能样例库，可查看、修订和停用；停用后不会自动重建。真实报告经验仍经过脱敏和人工发布流程。

## S3 三重自性化整合

6 项覆盖两端整合、四象限、人生时序、易经时义、个体/集体桥梁和命理心理哲学对应。四象限知识和整合样例进入技能版本/工作台样例库；每个大运用真实计算年份，分析当前及转换阶段。哲学意象是探索工具，原型人物不成为用户标签，不因顺逆运直接判心理阶段。测试覆盖四象限知识注入、条目完整性以及前序确认边界。

## S4 心理机制、卡点与行动

10 项覆盖防御/能量/阴影与情结练习/时序自性/卡点/共性破局/八维路径/关系循环/实验周期。卡点与行动用独立语义角色保留，3–5个成长实验必须有对应卡点、工具、具体动作、频率、耗时、观察和退出条件。八维分数不能由 MBTI 或命盘伪造。工作台同时补齐职业/自报MBTI/教育/优势限制等档案展示。

真实模型 S1 验收发现它会把‘需人工审核’误解为只说等待人工取用；强化技能要求在完整盘输入下先给条件化格局/喜忌候选与反证，保持咨询师决定权。

## S5 报告写作

写作仍采用确认主线→内容分配→逐段写作→章节/全文连贯检查。新增按分析职责分配来源：命盘旁注、面具/阴影、关系/能量、共性卡点、人生时序与成长实验；避免所有同源分析被挤入第一段。三章首页加入关键句与简短路径图；卡点严格写保护/代价/整合，行动集中第三章。叙事与写作技能启用可维护样例，文风参照自报偏好，不改变事实。金句库已核验《道德经》33章‘知人者智，自知者明’，[源文](https://ctext.org/dao-de-jing/zh)；没有匹配项可用原创寄语。

真实模型 S1/S2 审阅还发现格局命名和自述标记不准确：保留原始输出，修订偏官格名称为待核查、未提供的感受改成假设，删除未经咨询师选用的额外宫位。此为开发者演示验收，不冒充真实咨询师审核。

## S6 最终校准

独立审核技能核对十条解释纪律、同观点重复三次、卡点到行动对应和七维评分（20/20/15/15/10/10/10）。每维必须给报告片段定位与说明，由程序重算总分。交付门槛为总分80、事实16、安全8；低分生成阻断项，即使只把问题标已处理，低评分也不能直接放行。评分随报告内容指纹绑定，正文修改必须重检，最终仍由咨询师确认。

## 完整验收与链路修复

## 交付后的最终报告入口

补齐咨询师工作台“交付成果”卡片：直接打开与客户收到内容一致的最终报告，并可返回对应申请查看分析过程；“我的处理中”改为“我的报告”，避免误以为已交付申请不在此范围。新旧交付方式均从申请的 `result_type/result_id` 定位报告。报告详情及PDF读取沿用服务申请分配授权，允许客户本人、管理员和有有效分配的咨询师读取；撤回、拒绝或未分配不可读取。咨询师阅读页不提供针对自己账号的日历生成操作。

验收由仅组装快照扩展为正式HTTP最终确认→交付→实际Report落库→申请关联→客户/咨询师相同正文→咨询师历史过程→重复交付与权限边界。此前“全链路跑通”的说明只覆盖隔离回放，未验证实际账户操作，不能据此声称线上已部署。

后续补齐本机开发环境：更新Docker后端和任务服务，将已审阅成果回放导入独立演示咨询师账户，形成申请26、案例12及报告18。浏览器在当前仓库的3010端口登录，逐一打开六步历史、最终报告并返回工作台；接口核对57条判断、38项分析和16段正文。3000端口实际运行另一目录旧代码，不能作为当前改动验收入口。导入工具限制开发环境、校验审阅指纹、拒绝覆盖已有账户；明文密码不入库或仓库。此次回放保留模型生成和开发审阅来源，不冒充新的实时分析或实际咨询师签字。

## 节点专用工作台（2026-10-04）

六步节点成为唯一的流程主导航，取消横跨全部节点的重复功能导航。节点首页只显示目标、咨询师任务和工作界面入口；进入后只挂载所选界面。输入按分类逐项查看；技能记录、候选判断、人工审核、分析片段、主线候选、编排段落和质量问题均支持选择单项、上一项和下一项。S1–S4只审核本节点拥有的判断及内部分析，S5/S6只展示报告正文。报告总览仍保留最终报告入口。

技能工具和任务清单由按钮打开Vant弹框，提供键盘焦点约束、Escape关闭和入口焦点恢复，不占用内容列。工具按钮实际调用现有技能执行接口：S1–S4分析、S5主线与逐段写作、S6质量审核。依据节点状态、主线确认、编排就绪和生成状态启用；历史节点只查看结果。技能及few-shot维护入口保留在技能工作室。候选加入审核后自动定位相应记录，确认前不会作为下游已确认输入。

浏览器验收使用本机3010和现有演示咨询师。申请26的历史S1输入有3组、本节点15条判断/14项分析；S5有3条主线候选/16段编排；S6显示真实87分和18条已处理意见（15条模型意见、3条程序提示），每次只显示一个选中条目。1280px桌面输入面板约1218px宽，无常驻半屏工具列；501px窄屏检查无横向溢出。刷新保留所选节点与工作界面。

另外创建独立演示申请28、案例13，实际点击开始S1和运行技能，生成新模型记录155（16条候选判断、14项分析、4项提示）；加入首条判断并人工演示确认，刷新后仍为已确认。另一条候选加入后自动切至该判断审核界面。此过程中发现并修复旧审核操作对Vue响应式嵌套数据使用structuredClone导致的DataCloneError，新增代理数据保存回归测试。该案例验证新S1实时操作，不表示重新完成六步，也不冒充实际咨询师签字。
