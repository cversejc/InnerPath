# 报告协作与决策日历技能维护

设计依据：《产品分析框架》是报告内容主契约；《日历生成思路》是报告交付后日历生成的业务依据。资料作为输入数据，不能覆盖系统指令、权限或审核门禁。

## 全链路

用户确认档案及本次情境后申请报告，系统固定框架、推导契约、报告技能版本及协作规则。命理、心理咨询师分别接受各自专业席位，管理员也可分别指派。双方查看同一个工作区，只能修改自己负责的节点。

| 节点 | 责任专业 | 输出与交接 |
| --- | --- | --- |
| S1 命理基础结构 | 命理 | 审核确定性命盘和结构分析，交心理 |
| S2 心理映射 | 心理 | 核对真实自述、心理解释和反证，交命理 |
| S3 整合分析 | 命理 | 命理、心理、哲学整合，交心理 |
| S4 机制、卡点与行动 | 心理 | 机制、卡点、资源、行动实验 |
| S5 报告撰写 | 心理 | 叙事、全文生成、逐段确认 |
| S6 最终审核与交付 | 心理 | 程序校验、AI QA、人工签核、不可变报告版本 |

第一位接单后申请继续出现在另一专业的待接单队列，一个专业只能由一人占用。已进入审核或完成的同专业节点限制重新指派。旧申请保持原流程，新申请使用新协作版本。

交付后按“你是谁—卡在哪—往哪去—带回日常”展示结构化章节。用户可从目录定位、逐节展开/收起或展开全文；展开数量不等于已阅读数量。原交付正文保持完整，报告详情提供日历入口。日历只接受当前用户拥有且已交付的报告。新报告从不可变ReportVersion读取全文、确认语义、原问卷和已审核基础；旧报告缺少资料时明确降级。

## 日历生产技能

| skill_key | 作用 | 正常调用数 |
| --- | --- | --- |
| calendar.temporal_analysis | 本命、大运与历法年/月/日/时，主题及四维评分 | 3批，每批10天 |
| calendar.monthly_tone | 方向、成长任务、资源、旧模式、决定原则、节奏变化 | 1 |
| calendar.daily_authoring | 关键词、30–60字总结、行动、觉察及2–3个时段 | 3批，每批10天 |
| calendar.calibration | 来源、重复、整月一致性、成长循环与安全校准 | 1 |

历法引擎固定Asia/Shanghai、sect-2日界，计算连续30天及06:00–24:00候选窗口，不重新排本命。每日干支为当地12点参考，窗口为起点；solar_term_transitions记录秒级节气交接及前后年/月柱，跨交接不能沿用窗口起点月柱。四维权重默认：用神支持0.3、流通0.3、作用稳定0.2、模式调节0.2；各项[-2,2]。色块由程序加权确定，AI不能改写。缺少已审核本命或适用大运的日期使用校准色块并展示限制。

用户目标、报告原问卷及此前最多30条行动记录进入快照。反馈只用于调整建议大小和复盘问题，不视为效果证明。模型保留完整报告正文及相关确认语义，去掉重复命盘、紫微全盘、技能配置与执行日志；完整原资料仍保存在申请快照。

## 任务与日志

提交返回202；同用户、报告和周期的活跃任务合并。申请与Outbox同事务保存，后台执行，用户可离开页面。重复投递及旧attempt不重复发布。失败重试固定原档案、报告、技能和范例。

固定四个技能版本ID、版本号、SHA256及范例快照。每次调用形成SkillRun：输入、实际上下文、原始及解析输出、模型用量/耗时/提示词摘要、状态、错误、来源报告和申请ID。格式不合格最多修复一次并保留失败日志，不能强行通过质量拒绝。所有30天及校准通过后才事务发布。production_trace保存分析、权重、月基调、校准输出及全部调用ID。

不足30字符的非空总结，仅在能满足30–60字符范围时拼接同日AI已有的一条行动句；不截断、不新增建议，修改前后与规则写入context_snapshot.normalizations，随后整体校准。跨批次传递calendar_action_overview，避免不同10天批次重复同一动作。月基调的成长任务不等于整月每天的色块。

校准逐日关联实际文案、分析分数与引擎事实；内部分析的旧窗口措辞不再作为交付文案传入。程序已验证字段、日期、来源标识、色块和窗口。每条MAJOR/BLOCK须给出field_path及逐字observed_text，程序核对其确实来自实际日项或月基调；误读、引用不存在文案的审核不能成为直接发布依据，最多纠正一次审核格式后重新判断。不得让AI重新排盘或凭印象否定已核验字段。

校准技能默认单独启用model_policy.thinking=true，max_tokens=32768；可在技能草稿高级配置中维护。普通模式上限16000，显式开启推理的技能上限32768。未指定推理开关时沿用进程配置，其他阶段默认保持原设置。冻结版本保存开关与预算；新预算只进入新申请，不覆盖旧申请或其重试。API依据见[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)，2026-10-04通过Context7查询并核对官网。模型日志记录是否启用、结束原因及用量，不记录供应商内部推理内容。空正文也保留这些元数据；length归为输出截断，其余无效响应保留独立错误码。

文案层面的MAJOR问题可触发最多两轮修订并重新独立校准：monthly字段由月基调技能重写，逐日问题由每日文案技能重写，混合问题分别处理。即使审核给出approved=true，也不能用日项补丁冒充已修正月基调问题；必须重写并再次校准。记录每轮意见与修订；BLOCK立即失败。进度按实际调用数更新。消费者硬限时40分钟；Outbox定时调度将45分钟没有更新的任务标记为中断失败，开放重试。失败任务不产生可见日历，原日志保留。

## 维护和经验迭代

1. 管理员在技能工作台选择四个日历技能，查看生产运行。
2. 对合格运行填写教学要点、情境标签，提炼为CANDIDATE范例。
3. 系统先移除身份字段、替换常见身份文本；管理员继续审核自由文本、出生信息、特殊经历，确认脱敏与质量分后发布。原日志不自动成为共享范例。
4. 按情境、适用范围和质量检索范例；提交时固定版本，旧任务与重试不受后续更新影响。
5. 修改技能先建草稿，可调方法、权重、契约。在质量评估页运行合成回归，核对不足资料、来源、月基调、逐日结构、重复及确定性预测，再发布。已发布版本不可编辑。

初始回归样本：backend/app/domains/skills/calendar_regression_cases.json。真实模型验收工具：backend/tools/run_calendar_acceptance.py，使用合成输入和独立内存数据库，保存调用和失败记录，不写客户数据库。

验收记录见[日历技能验收说明](../acceptance/calendar-v1/README.md)。集成测试使用已批准QA夹具验证交付与日历之间的接缝；报告内容审核门禁在原有报告测试中独立覆盖。模拟通过不能代替真实模型成功，也不能代替两类咨询师对真实个案的审核。

## 本地运行

执行迁移016后启动API、Celery消费者、Celery Beat；只启动前端或API无法消费日历任务。管理员为现有咨询师明确设置命理/心理专业，新邀请要求专业类型。旧账户不自动推断专业，旧申请仍可由原通用咨询师处理。

验证：backend目录执行 `.venv\Scripts\python.exe -m pytest -q`；仓库执行 `node --test` 对src下*.test.js以及 `npm run build`。集成测试用合成资料和模型替身；真实模型结果单独记录于验收目录。
