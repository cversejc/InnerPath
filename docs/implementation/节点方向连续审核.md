# 节点整体审核与交接

## 咨询师工作顺序

上游输入核对 → 运行 AI 分析 → 加入本节点待审内容 → 整体审核判断 → 整体审核分析 → 节点复核与签核。

S1–S4 保留 AI 分析、判断审核、分析内容和节点复核等分步入口；S1 另有出生资料与时间核对、程序计算。AI 候选先整体加入待审范围，不因被纳入而自动确认。咨询师分别确认判断组和分析组；存在具体问题时仍可针对条目修改、拒绝或暂缓。

S1 的出生资料页并列展示申请档案与程序换算，正常资料一次确认；缺失、冲突或口径异常时补问或修订并说明依据。程序计算结果完整保留，常规计算由程序校验；只有排盘异常时才进行人工修订。

## 处理规则

- 整体阅读本节点判断及资料来源；只对实际争议、错误、反证或依据不足的判断单独处理。
- 判断确认不会代替分析确认。分析内容仍需完整阅读，检查来源、覆盖、推导边界和缺失信息后再整体确认。
- 修改、拒绝或暂缓一条内容时，同步处理依赖它的分析和引用；已确认的前序节点仍只读，来源需要更正时退回对应负责人。
- 修改内容沿用版本冲突检查，并只使受影响的阶段和下游成果重新复核。保存失败应保留编辑内容和位置。
- 完成各阶段后仍须进入节点复核；签核检查所需阶段当前有效，并确认没有阻断或重要问题。
- 同类问题（同类型、同严重度）聚合成一张卡片整体处理：核对涉及内容后填写一次处理依据，对整组生效。每条问题仍写入独立的处理状态、处理人、处理时间与依据，签核仍逐条检查是否关闭。阻断项和单条异常不进入整组处理，必须单独处理。
- 阶段确认成功后自动进入下一审核页：先解除编辑忙碌状态再广播前进，导航守卫只拦真正的编辑中切换；警告提示随忙碌状态解除自动清除。
- 出生资料已有确认内容但阶段确认无效（内容变化或缺少确认记录）时，仍提供一次“确认资料与换算结果”，避免节点签核被缺失的阶段确认永久阻塞。
- 已完成节点回看时展示本节点完成时的检查结果与处理记录，不使用当前快照的程序检查替代；检查结果来源在界面上标注为历史记录。节点复核页对已完成节点保持只读渲染，状态显示「已完成 · 仅供回看」，阶段确认显示「已完成时确认（后续内容已更新）」，不要求重新确认。

## 实现边界

AI 候选及引用的展示位于报告内容前端领域；加入待审范围与阶段确认调用对应的报告 API。HTTP 适配器调用既有应用编排，由内容领域建立版本并验证引用。AI 原始运行结果保持可追溯。

章节与全文连贯性检查、交付前质量检查都按案例创建时冻结的技能版本运行，案例处理期间发布的新版本不会替换正在执行的案例。

来源有效性、节点权限、运行激活版本、当前内容版本与确认引用均继续由后端校验。每个阶段的确认记录绑定对应内容范围指纹、策略版本、操作者和时间；候选自身携带的状态不能作为已审核结果。

同类问题整组处理的接口为 `POST /report-cases/{case_id}/steps/{step_key}/review/issues/resolve-group`（节点检查问题）与 `POST /report-cases/{case_id}/quality/issues/resolve-group`（交付前质量检查问题），响应仍返回逐条问题记录；两类接口都不接受阻断项，阻断项必须单独处理。

## 写作与最终审核的接续

S5 先确认主线和编排，再顺序生成报告并展示进度。生成及全文连贯检查完成后，进入完整报告审阅，按需从正文查看来源并局部修订；正文修订会使连贯检查及报告阶段确认失效，必须针对当前全文重检后再整体确认，普通段落不需要单独签核。

S6 保留质量检查、问题处理、完整正文复核和最终交付。内容变更或重跑质量后，签核绑定当前报告与最新质量运行；检查不再要求咨询师另行重复触发“完整节点检查”。阻断和重要问题仍必须处理，普通表达建议可略过。

编辑和保存期间阻止误切换节点及工作界面；保存失败保留输入。正文版本冲突后保留修改，并允许取消修改或载入最新版。

## 节点完成与专业归属

完成节点后打开下一待办节点总览。节点只激活为待开始；负责人明确点击“开始本节点”后进入上游输入。S1–S3 归命理咨询师，S4–S6 归心理咨询师；跨专业或未接单时明确说明交接与分配状态。

旧报告的流程版本和节点任务已冻结，仅修改新流程不能修复已有任务。迁移 018 纠正仍处于 PENDING/READY、从未开始的旧心理归属 S1–S3，并依据申请的命理负责人分配。原始流程定义、申请快照和已完成节点保持原有历史；任务配置记录旧归属，审计日志记录修正。已开始工作的节点不由迁移静默改派。
