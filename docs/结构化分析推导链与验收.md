# 结构化分析推导链与验收

维护日期：2026-10-04。内容基线仍为[产品分析框架](产品分析框架.md)，延续[分析到报告的映射契约](产品分析框架到报告的映射契约.md)。本次新增 `report-reasoning-2026-10-04-v1`，不替代原38项分析、16项报告内容职责和4项全文规则。

## 实例和工作流固定技能版本

新发布的 `report.production` WorkflowVersion 保存 `definition_json.skill_bindings`，包含S1–S4分析、主线规划、逐段写作和最终校准的7项技能；步骤额外配置的技能也一并固定。每个条目保存具体数据库ID、版本号和规范SHA256摘要。

新案例复制这些绑定到 `application_snapshot.skill_bindings`。沿用没有绑定的旧工作流创建新案例时，在创建时固定当时的技能；已经存在的案例不自动变更。后续各入口通过统一解析函数取固定版本，不能查询“最新发布”替换它。显式传入另一版本也会被运行创建门禁拒绝。

同一工作流版本创建的新案例继续使用其绑定；发布新技能不会自动升级该工作流或旧案例。需要采用新技能时，创建并发布新工作流版本。固定版本被退休或规范与摘要不一致时阻断运行，不能静默回退到其他技能。

权威实现：[技能绑定](../backend/app/domains/skills/bindings.py)。绑定本次没有新增数据库表或迁移。单次运行仍保存模型trace、输入、技能ID和提示摘要；本文没有宣称第三方模型服务的实现永远不变。

## 八项结构化分析

新案例将推导契约完整固定在 `application_snapshot.reasoning_contract`。分析片段通过已有Revision API提交 `structured_analysis`，保存在不可变片段的 `source_snapshot.structured_analysis`。该记录与普通 `framework_coverage` 同时存在：前者保存分析结构，后者声明框架内容覆盖。

| 分析片段 | details必须包含的字段 | 核对重点 |
| --- | --- | --- |
| `analysis.s2.mapping` | self_description、core_belief、authority_origin、counterexample | 自述、意识自我、底层信念、权威内化及反证；不补造早期经历 |
| `analysis.s2.complex` | trigger、emotion、automatic_thought、defense、protection、repetition_cost、reality_check | 触发→情绪/信念→防御→保护→长期重复，并说明现实核对 |
| `analysis.s3.self` | dominant_pole、excluded_pole、integration | 对立两端及两端共同存在的整合任务 |
| `analysis.s3.quadrant` | archetype、learnable_capacity、fit_reason、boundary | 中式原型、可学习资源、适配理由与比喻边界 |
| `analysis.s3.timeline` | periods、uncertainty | 每期start_year/end_year、interaction、theme、capacity、old_pattern；年份必须来自该片段实际引用的计算证据 |
| `analysis.s4.energy` | charging、draining、reality_check | 充电、耗电、实际反馈与反例 |
| `analysis.s4.functions` | exploration、valuation、execution、feedback、tension | 本人的加工路径和张力，无自报不推断MBTI或八维分数 |
| `analysis.s4.breakthrough` | common_mechanism、resource_translation、capacity_gap、integration_task、tool_rationale | 多卡点共性→资源转译→能力缺口→整合任务→工具理由 |

统一记录：`{status, reason, quote, follow_up_questions, details}`。FULFILLED必须包含全部规定字段；DEFERRED可以details为空，但正文须有暂缓说明和可回答补问。核心推导不能用NOT_APPLICABLE省略。quote必须逐字出现在同一片段content中，不能拿问卷、上游分析或details中没有进入正文的句子冒充。

内部阶段地图的每期起止必须匹配已引用的 `SYSTEM_CALCULATED` Evidence中 `bazi_facts.dayun`。没有计算依据时应明确暂缓，不能为了完成结构补造年份。原局互动是否解释到位由独立语义校准与咨询师核对，年份匹配本身不证明专业解释正确。

## 资源到行动的来源链

每个确认ACTION的 `structured_data.reasoning_path` 保存：

```text
resource_refs → regulation_function → capacity → reality_gap
              → block_refs → integration_task → tool → rationale → ACTION
```

- resource_refs引用已确认RESOURCE、USEFUL_GOD、STRUCTURE或SELF_DIRECTION Finding，不能用PERSONA、分析片段ID或不存在的ID替代。
- block_refs必须与该行动原有block_refs一致，且目标确为已确认BLOCK。
- evidence_refs必须包含当前案例实际存在的用户自述依据，只有命盘计算不能代替现实需要。
- tool必须与行动method一致；频率、耗时、具体步骤、观察和退出条件继续沿用原Action契约。
- 确认行动时将卡点和资源写入DERIVED_FROM关系，现实依据合并入行动Evidence引用。审核保存顺序为资源/卡点在前、行动在后。

编排向成长实验片段分配这些具体来源，保存 `required_finding_refs`。正文生成必须实际使用并记录它们，不能只给出通用建议。INTERNAL_ONLY资源可以参与推导审核，不能作为新增心理结论直接发表或直接复制内部分析原文。

主线候选的priority_blocks是3–5个具体卡点，每项恰好一个真实BLOCK且有行动回应；不接受以三章目录、资源、能力或行动冒充卡点。同一候选不能重复同一卡点。三章安排属于narrative_arc，旁证属于supporting_findings。

权威实现：[推导契约与校验](../backend/app/domains/content/reasoning_contract.py)。程序检查字段、来源、角色、年份和实际正文引用；资源如何转成能力、反证是否改变判断、工具是否适合现实条件，由独立Validator和咨询师判断。

## 真实模型开发验收

工具：[run_framework_acceptance.py](../backend/tools/run_framework_acceptance.py)。使用项目现有模型网关；不写入开发或生产数据库，不对客户交付，不记录咨询师已经签字。输入是明确标注的合成用户，不能将技术验收当作真实客户专业准确性证明。

四个案例：资料完整且无MBTI、缺时辰且无MBTI、自述明确否定讨好/权威恐惧假设，以及轮班照护长辈、已自报MBTI、偏好简洁内容且每日时间受限。新案例核对照护分工、工作交接、转岗目标和8分钟/25分钟时间预算是否进入行动设计。每个验收目录保存固定技能规范及摘要、完整输入、逐阶段输出、失败原文、模型trace、主线编排、报告正文和独立审核。失败重试不会自动补齐或修正正文来伪装通过；旧失败文件保留。

运行示例（在backend目录，使用PowerShell）：

```powershell
.\.venv\Scripts\python.exe tools\run_framework_acceptance.py --scenario full --output ..\docs\acceptance\framework-v1\full
```

输入和规范固定后可续跑；缓存输出仍须通过当前校验规则。被新门禁判为不合格的旧缓存会保存invalidated副本，再由模型重新生成。模型因长度限制结束时直接标记 `skill_output_truncated`，不尝试把截断结果当作完整报告。

## 自动回归与后续边界

新增回归包括：七项技能跨发布仍固定、换版本运行被拒绝、退休/篡改版本不回退、核心结构缺字段、证据不足暂缓、资源角色错配、行动卡点错配、单独计算依据冒充现实依据、错误大运年份、内部资源未进入正文来源记录、三章目录冒充卡点、输出截断不放行。后端全量测试命令仍为 `.\.venv\Scripts\python.exe -m pytest -q`。

四个真实模型合成案例均完成38项分析、17段报告与16项独立内容审核；当前修订分数分别为85、87、87、86。轮班照护样本在三轮修订后越过分数门槛，但仍有5条MINOR意见，未放行交付。各轮分数、失败与修订记录见[验收结果](acceptance/framework-v1/验收结果.md)。

后续优先校准全文去重和独立审核的稳定性，并由咨询师复核符号转译、现实依据和工具适配。评分通过不代替这些复核。修订工具使用`--repair 1/2/3`生成独立修订目录，保留原稿与原审核；修订时不改变来源中的已确认Action条件。

局部STALE、报告到日历的结构化投影及分组审核权限仍属后续工作；本次没有改变它们。真实客户验收需要资料完整且经本人确认的问卷，以及具备专业能力的咨询师审核。
